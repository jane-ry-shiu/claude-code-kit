# Requirement Summary

Produce a light, plain-language summary: what it does, expected behavior, operations, logic. Aim for the Phase-1 summary depth shown in `references/example-record.md` — NOT the deep assessment (that is Phase 3).

If the source is an OpenSpec change, read `proposal.md` + `specs/*/spec.md` (and `design.md` if present). Reading is trivial once the folder is given.

Do not move to deep assessment until the summary + scope are confirmed by the user.
